# Chromium 页面采集器

一个本地运行的 Chromium Manifest V3 扩展，用于按批次保存当前标签页的 Fetch/XHR 接口增量、页面截图和备注。版本为 0.2.1。扩展不上传采集数据，也不自动遍历页面或提交表单。

## 安装

1. 下载或克隆本仓库。若使用发布包，先将 ZIP 解压到本地目录。
2. 在 Chrome 打开 `chrome://extensions`，启用开发者模式，选择“加载已解压的扩展程序”。
3. 选择仓库中的 `extension/` 目录；若使用发布包，选择包含 `manifest.json` 的解压目录。

运行扩展的电脑无需 Node.js、本地服务器或其他依赖。更新文件后，在扩展管理页重新加载扩展。本项目不是签名的商店扩展；企业策略禁止加载或调试时，请联系管理员。

清单声明最低 Chrome 版本为 105，旧内核提供基础采集。跨进程 iframe 的子会话监听需要较新内核，完整兼容范围以实际验证为准，详见[验证记录](docs/tasks/batch-capture/status.md)。扩展使用 `activeTab`、`debugger`、`downloads` 和 `storage` 权限，连接时浏览器可能显示调试提示。

## 使用

1. 打开已获准采集的页面，点击扩展图标，或按 `Alt+Shift+Y`。
2. 选填备注，点击“开始本批”。工具先开始记录，再自动刷新业务页一次，自动保存首份快照。不要在重载可能改变数据或丢失未保存内容的页面开始本批。
3. 保持扩展的记录状态页打开，回到业务页自行切换类别、筛选或翻页。可在状态页点击“返回业务页面，保持记录”；关闭普通备注面板不会停止记录。
4. 每次需要留档时打开扩展面板，选填本次备注，点击“保存一次”。工具保存此刻的整页截图和未成功留档的接口增量，随后继续记录，不再刷新页面。
5. 需要留档时先点击“保存一次”，待保存完成后再点击“结束本批”。结束会立即停止记录并丢弃未保存缓存，不等待请求、不截图、不额外下载。在终态点击“关闭并返回原页面”；原标签页已关闭时，只关闭状态页。

同一时间只有一个活动批次，绑定开始时的浏览器标签页。业务页签、网页地址和 iframe 内容变化不自动拆批；其他浏览器标签页不自动加入。下一批首次采集会再次刷新一次。

首份准备最多等待 20 秒，不会因此结束整个批次。普通保存最多等已有请求 5 秒，尚未返回的继续跟踪，归入后续快照；保存期间新发起的请求也留给下一份。点击“结束本批”会丢弃这些尚未保存的记录，包括未完成请求。

某份文件下载失败时，点击“重试失败文件”；原截图和接口数据保持不变，已经下载成功的文件不主动重复下载。重试成功前不能保存下一份或正常结束。需要主动放弃时，工具会说明未保存数据的影响，已经下载的文件保留。

## 输出

同一批使用同一目录，每份快照使用递增序号，不会自动压缩采集结果：

```text
PageCapture/批次标识/
  001/page.json
  001/screenshot-full.png
  001/note.txt
  002/...
```

- `page.json`：顶层数组，每项只有 `request` 和 `response`。保留本次尚未成功留档的 Fetch/XHR 请求与响应及其实际 HTTP 方法，不限于 GET 或 POST。同一个接口的多次调用分别保留，没有新请求时为 `[]`。
- `screenshot-full.png`：页面当前已渲染内容的整页截图。超长页面整页截图失败时会尝试回退到当前视口；如果截图完全失败，该文件不会生成，状态页和备注会说明。
- `note.txt`：本次备注、批次和快照信息、统计、计时、请求类别和正文省略原因等诊断。接口诊断序号从 1 开始，与本份 JSON 数组顺序对应。

正常快照的三个文件全部下载完成后，才把本份接口标为已留档。截图完全失败时，JSON 和备注均下载成功即可按“缺图快照”留档，界面明确提示截图失败。

`response.bodySize` 是已知的正文传输字节数，无法可靠确定时为 `-1`。备注中的总传输量可能包含响应头。采集器不会自动滚动触发懒加载，也不会展开内部滚动容器；截图不能保证包含这些区域的隐藏内容。

## 范围与隐私

只导出浏览器分类为 Fetch 或 XHR 的请求；不记录 WebSocket/SSE 消息帧。扩展协议地址及浏览器可识别为扩展发起的请求会从记录中排除；浏览器未提供来源时，无法可靠识别普通 HTTP/HTTPS 地址背后的扩展请求。过滤只影响导出，不拦截网络请求。子页面覆盖受内核 API、页面结构和企业策略影响，覆盖受限时应查看界面与备注中的诊断。工具不暂停子页面脚本，新建跨进程 iframe 从创建到监听启用之间可能存在请求记录空窗。Service Worker 发起请求的完整覆盖尚未验证。

JSON、XML、纯文本和 GraphQL 响应可保存正文；二进制及其他类型只保留元数据。单条响应正文上限为 2 MiB，尚未成功留档的正文累计上限为 24 MiB，超限、未完成等情况会在备注中说明。multipart 和无法按支持的格式脱敏的请求正文会省略。

尚未保存的记录最多 2000 条，记录元数据最多 8 MiB；批次请求标识最多 10000 个、合计 4 MiB，子会话最多 128 个。达到记录或跟踪资源上限时，工具停止继续记录并提示不完整，保留已有数据供补导出。成功留档后释放对应记录和正文缓存。

业务页关闭或记录连接断开时，工具停止继续记录，不自动重连或刷新；记录状态页仍在时，可点击“补导出已收数据并结束”。记录状态页被关闭、浏览器退出或扩展重载后，不保证恢复未保存缓存，已经下载的文件保留。

认证类请求头，以及 URL 查询参数、JSON 和 URL 编码表单中名称匹配常见敏感关键词的字段会脱敏。普通文本正文不做字段级脱敏，其他正文和截图仍可能包含敏感信息；分享前请检查所有文件。真实采集数据、截图、备注和凭据应保留在仓库外。

## 开发与打包

开发验证需要 Node.js；项目没有第三方 npm 依赖。在仓库根目录运行：

```powershell
npm test
npm run check
npm run package
```

`npm test` 运行 Node VM 回归检查，`npm run check` 检查扩展 JavaScript 语法；这些检查不能替代真实浏览器验证。`npm run package` 默认调用 Windows PowerShell 5.1。如果环境中只有 PowerShell 7，可直接运行 `pwsh -NoProfile -File scripts/package.ps1`。

打包从扩展清单读取版本，将 `extension/` 的内容打包为 `dist/chromium-page-capture-<version>.zip`，并生成同名 `.zip.sha256` 文件。打包不安装依赖、不上传文件。
