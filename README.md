# Chromium 页面采集器

一个本地运行的 Chromium Manifest V3 扩展，用于按批次保存当前标签页的 Fetch/XHR 请求、响应正文、页面截图和备注。版本为 0.3.0，导出格式为 formatVersion 2。

## 安装

1. 下载或克隆本仓库。若使用发布包，先将 ZIP 解压到本地目录。
2. 在 Chrome 打开 `chrome://extensions`，或在 Edge 打开 `edge://extensions`，启用开发者模式，选择“加载已解压的扩展程序”。
3. 选择仓库中的 `extension/` 目录；若使用发布包，选择包含 `manifest.json` 的解压目录。

运行扩展的电脑无需 Node.js、本地服务器或其他依赖。更新文件后，在扩展管理页重新加载扩展。本项目不是签名的商店扩展；企业策略禁止加载或调试时，请联系管理员。

清单声明最低 Chrome 版本为 105，旧内核提供基础采集。跨进程 iframe 的子会话监听需要较新内核，完整兼容范围以实际验证为准，详见[验证记录](docs/tasks/readable-export/status.md)。扩展使用 `activeTab`、`debugger`、`downloads` 和 `storage` 权限，连接时浏览器可能显示调试提示。

## 使用

1. 打开已获准采集的页面，点击扩展图标，或按 `Alt+Shift+Y`。
2. 选填备注，点击“开始本批”。工具先开始记录，再自动刷新业务页一次，自动保存首份快照，备注用于首份子目录名。开始前确认业务页可以安全刷新。
3. 保持扩展的记录状态页打开，回到业务页自行切换类别、筛选或翻页。可在状态页点击“返回业务页面，保持记录”；关闭普通备注面板不会停止记录。
4. 每次需要留档时打开扩展面板，选填本次备注，点击“保存一次”。工具保存此刻的整页截图和未成功留档的接口增量，备注用作本次子目录名，完整备注也保存在 page.json 中。
5. 需要留档时先点击“保存一次”，待保存完成后再点击“结束本批”。结束会立即停止记录并丢弃未保存缓存，不等待请求、不截图、不额外下载。在终态点击“关闭并返回原页面”；原标签页已关闭时，只关闭状态页。

同一时间只有一个活动批次，绑定开始时的浏览器标签页。业务页签、网页地址和 iframe 内容变化不自动拆批；其他浏览器标签页不自动加入。下一批首次采集会再次刷新一次。

首份准备最多等待 20 秒，不会因此结束整个批次。普通保存最多等已有请求 5 秒，尚未返回的继续跟踪，归入后续快照；保存期间新发起的请求也留给下一份。点击“结束本批”会丢弃这些尚未保存的记录，包括未完成请求。

某份文件下载失败时，点击“重试失败文件”；原截图和接口数据保持不变，已经下载成功的文件不主动重复下载。重试成功前不能保存下一份或正常结束。需要主动放弃时，工具会说明未保存数据的影响，已经下载的文件保留。

## 输出

同一批使用一个外层目录，每份快照按备注命名。备注重复时添加 `_2`、`_3` 后缀，未填写时使用该份序号。目录名会处理 Windows 非法字符、设备名和过长名称，处理后再次检查重名。

```text
PageCapture/批次标识/
  客户列表/page.json
  客户列表/screenshot-full.png
  在职员工/page.json
  在职员工/screenshot-full.png
  在职员工_2/...
  004/...
```

- `page.json` 保存 `formatVersion`、`capture` 和 `entries`。capture 包含完整备注、页面、截图范围和实际异常，entries 中每项为一对 request/response。没有新接口时 entries 为 `[]`，采集状态仍可查看。
- `screenshot-full.png` 保存页面当前已渲染内容的整页截图，整页失败会尝试当前视口。完全缺图时，page.json 中的截图状态和警告说明原因。

正常快照的 JSON 和 PNG 均下载完成后，才把本份接口标为已留档。完全缺图时，包含缺图说明的 JSON 下载完成即可按缺图快照留档。失败重试使用首次冻结的内容和目录，成功文件保留。

formatVersion 2 采用对象作为顶层容器，旧版顶层数组的调用方需要改为读取 `entries`。具体字段及完整示例见[导出规格](docs/tasks/readable-export/spec.md)。

请求保留方法、地址、查询参数、请求头和正文，响应保留状态、响应头和正文。同名查询参数和表单字段分别保留。所有符合范围的接口调用都会进入增量，包括 `0`、`false`、`null`、空数组和 HTTP 错误响应，服务端字段及其层级完整保留。

JSON 的 `bodyText` 保留按规则脱敏后的正文文本，安全时另提供结构化 `body` 便于阅读。大整数、精确小数、重复 JSON 键或预算不足时，优先保留文本，并说明阅读视图的省略原因。HTML、XML 和其他文本保存原文。`bodyStatus`、`bodyError` 和 `bodyWarnings` 区分空正文、实际缺失、格式限制及脱敏范围。

截图范围限于当前已渲染内容。懒加载和内部滚动容器的隐藏部分需要用户先在业务页操作。

## 范围与隐私

只导出浏览器分类为 Fetch 或 XHR 的请求，WebSocket/SSE 消息帧在采集范围之外。扩展协议地址及浏览器可识别为扩展发起的请求会从记录中排除，来源未提供时覆盖受限。子页面覆盖受内核 API、页面结构和企业策略影响，限制在界面和 capture.warnings 中显示。新建跨进程 iframe 从创建到监听启用之间可能存在请求记录空窗。Service Worker 发起请求的完整覆盖尚未验证。采集过程由用户手动浏览和查询触发，数据保存在本机。

单个请求或响应正文的文本上限为 2 MiB，未成功留档正文累计预算为 24 MiB。正文文本优先，展开阅读视图按剩余预算生成。正文超限或浏览器取不到正文时，保留可取得的请求/响应信息和明确原因。二进制响应保存类型及省略原因。multipart 保留可取得的文本字段及文件描述，原始文件字节省略，部分取得情况有说明。

尚未保存的记录最多 2000 条，记录元数据最多 8 MiB；批次请求标识最多 10000 个、合计 4 MiB，子会话最多 128 个。达到记录或跟踪资源上限时，工具停止继续记录并提示不完整，保留已有数据供补导出。成功留档后释放对应记录和正文缓存。

业务页关闭或记录连接断开时，工具停止继续记录，不自动重连或刷新；记录状态页仍在时，可点击“补导出已收数据并结束”。记录状态页被关闭、浏览器退出或扩展重载后，不保证恢复未保存缓存，已经下载的文件保留。

认证类请求头，以及 URL 查询参数、JSON、URL 编码表单和可解析 multipart 字段中的常见敏感名称按规则脱敏。JSON/表单正文无法可靠解码或脱敏时，明确省略，base64 回退也遵守同一规则。HTML、XML、普通文本和 GraphQL 原文采用原文保留，其字段级脱敏范围在 JSON 中标明，分享前需检查正文和截图。真实采集数据、截图、备注和凭据保留在仓库外。

## 开发与打包

开发验证需要 Node.js；项目没有第三方 npm 依赖。在仓库根目录运行：

```powershell
npm test
npm run check
npm run package
```

`npm test` 运行 Node VM 回归检查，`npm run check` 检查扩展 JavaScript 语法；这些检查不能替代真实浏览器验证。`npm run package` 默认调用 Windows PowerShell 5.1。如果环境中只有 PowerShell 7，可直接运行 `pwsh -NoProfile -File scripts/package.ps1`。

打包从扩展清单读取版本，将 `extension/` 的内容打包为 `dist/chromium-page-capture-<version>.zip`，并生成同名 `.zip.sha256` 文件。打包不安装依赖、不上传文件。
